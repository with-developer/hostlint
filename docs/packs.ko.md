# 정책 팩: 직접 만든 점검과 프로파일

정책 팩은 hostlint 자체 콘텐츠와 같은 형식으로 직접 만든 점검과 프로파일을 담은 디렉터리입니다. hostlint를
포크하지 않고도 팀의 기준(사내 기준, 고객 요구 사항, `/etc`에서 더 살펴볼 것 하나)을 점검할 수 있습니다. 배경이 된
결정은 [ADR 0012](adr/0012-policy-packs.md)에 있습니다.

[English](packs.md)

```sh
hostlint pack test ./acme-pack                 # 불러와서 점검의 테스트를 실행
hostlint pack show ./acme-pack                 # 검토하는 사람을 위해 팩이 하는 일을 보여 줌
hostlint scan --pack ./acme-pack -p x-acme-baseline
hostlint scan --pack ./acme-pack -p kisa-2026 -p x-acme-baseline   # 둘을 한 번에
```

## 팩이 할 수 있는 것과 없는 것

팩은 **새로운 능력을 더하지 않습니다.** 점검은 내장 점검과 같은 선언형 YAML과 같은 CEL 표현식이며, 컴파일되어
있는 수집기가 만든 사실을 대상으로 평가합니다. 수집기, 사실, 명령, 함수를 추가할 수 없으므로 아무것도 실행할 수
없고, 내장 점검이 읽을 수 없는 것의 내용도 읽을 수 없습니다. 민감 경로 거부 목록이 그대로 적용됩니다.

팩은 `hostlint.yaml`처럼 **신뢰하는 입력이지, 악의적인 작성자를 막는 샌드박스가 아닙니다.** 팩은 증거로 무엇을
보일지(파일 점검이 나열하는 이름·소유자·모드, 표현식이 보여 주는 사실), 어떤 수집기를 돌릴지, 그리고 프로파일을 통해
어떤 점검을 셀지와 심각도를 정합니다. 직접 쓰지 않은 팩은 쓰기 전에 `hostlint pack show`로 읽어 보고, 믿을 수 있는
사람의 팩만 쓰세요.

hostlint는 팩이 결과를 실제보다 좋아 보이게 만들 수 없도록 내장 콘텐츠보다 더 엄격하게 다룹니다.

- 모든 점검의 영역은 `x-`로 시작하고(`x-acme.motd-owned-by-root`) 모든 프로파일의 ID도 `x-`로 시작합니다. 결과의
  점검 참조만 봐도 팩의 점검과 내장 점검이 구분되며, 내장 콘텐츠나 다른 팩과 겹치지 않습니다.
- 프로파일은 다른 프로파일의 제목을 쓸 수 없습니다.
- 프로파일이 점검에 지정하는 매개변수는 점검의 기본값과 같거나 더 엄격해야 합니다(더 약한 설정을 받아들이려면
  직접 점검을 작성하세요). 다른 종류의 매개변수는 기본값을 유지해야 합니다.
- 컨트롤은 매핑한 점검 중 가장 높은 심각도로 올려지는데, `--fail-on`이 컨트롤의 심각도로 판정하기 때문입니다(점검
  시 알려 줍니다).
- 파일 점검은 경로를 최대 10개까지, 각 경로의 와일드카드는 최대 2개까지 나열할 수 있고, `/proc`, `/sys`, `/dev`
  아래는 안 됩니다.
- 점검의 `remediation`에는 제어 문자가 없고 줄바꿈과 탭만 있습니다. 실패한 점검의 `remediation`은 `hostlint explain`, JSON 결과, SARIF 도움말, HTML 보고서, 대시보드에 보이므로 글자만 허용합니다.
- 모든 점검에는 내장 점검과 같이(ADR 0006) PASS 테스트, FAIL 테스트, 입력이 없거나 쓸 수 없거나 불완전한 경우의
  테스트가 필요합니다.

## 구성

```text
acme-pack/
  pack.yaml
  rules/x-acme/motd-owned-by-root.yaml     # 점검 하나, rules/<영역>/<이름>.yaml, ID는 x-acme.motd-owned-by-root
  profiles/x-acme-baseline.yaml            # 프로파일 하나, profiles/<id>.yaml
```

`pack.yaml`:

```yaml
format: 1                  # 팩 형식의 버전
name: acme                 # 케밥 케이스, 결과가 팩을 이 이름으로 부름
version: 1.2.0             # 영문자, 숫자, . _ + -
description: Acme's baseline            # 선택
requires_hostlint: v0.15.0              # 선택: 팩이 동작하는 가장 오래된 릴리스
```

점검과 프로파일은 [CONTRIBUTING](../CONTRIBUTING.md#how-a-check-is-built)과 [규칙 참조](rules.md)에 설명한 대로
작성하며, [`examples/policy-pack`](../examples/policy-pack)은 동작하는 작은 팩입니다. `hostlint pack facts`는 점검이 읽을 수 있는 사실을 나열하고, [사실 참조](facts.md)가 설명합니다. 프로파일은 내장 점검과 직접
만든 점검을 함께 매핑할 수 있습니다(위 영어 문서의 예시와 같습니다). 프로파일을 바꾸면 `revision`을 올리세요.

## 팩 사용하기

`hostlint scan --pack DIR`(반복 가능, `HOSTLINT_PACK`도 가능하며 `PATH`처럼 구분한 디렉터리 목록)은 팩을 내장
콘텐츠와 함께 불러오고, `--profile`로 팩의 프로파일을 고릅니다. `--profile`은 반복해서 여러 프로파일을 한 번에 점검할
수 있습니다(겹치는 점검은 한 번만 평가). 팩을 불러왔는데 그 프로파일을 하나도 고르지 않으면 팩을 조용히 무시한 채
점검하지 않고 오류를 냅니다. 팩은 hostlint를 실행하는 머신에서 읽으며, `--root`나 `--image-tar`를 통해 읽는 일도,
현재 디렉터리에서 저절로 찾는 일도 없습니다.

결과에는 어느 팩에서 나왔는지가 `scan.packs`에 이름, 버전, 다이제스트(읽은 파일의 경로와 내용을 정렬해 구한
SHA-256)로 들어갑니다. `hostlint diff`와 `hostlint report`는 서로 다른 팩이나, 같은 프로파일 리비전인데 내용이 다른
결과를 경고합니다. `hostlint.yaml`은 팩의 점검과 컨트롤을 참조할 수 있습니다(매개변수, 예외). 팩 프로파일의 컨트롤에
대한 예외는 프로파일의 다이제스트(`digest:`, 이를 요구하는 오류 메시지, 결과, `pack show`에 나옴)를 적습니다. 다이제스트는
컨트롤이 매핑하는 것과, 매핑한 팩 자체 점검이 하는 일을 모두 담습니다. 팩 작성자가 리비전을 바꾸지 않고도 둘 다 바꿀 수 있기
때문입니다.

`--verify-pack`은 점검 전에 팩 점검의 테스트를 실행하고, 테스트에 실패하는 팩으로는 점검하지 않습니다. 테스트는
실수를 잡을 뿐 악의를 잡지 못하고(작성자가 로직과 테스트를 모두 쓰므로), 호스트마다 시간이 드니 팩 자체의 CI에서
`hostlint pack test`로 실행하세요.

팩과 함께 점검한 결과도 `--push`로 보낼 수 있습니다. 결과에 팩의 이름·버전·다이제스트가 담기고, 플릿 서버는 다른 결과와
똑같이 그대로 보관합니다(docs/fleet.ko.md). 팩의 프로파일은 대시보드에서 고를 수 있고 호스트 페이지에 팩이 표시됩니다.
서버는 팩의 내용을 모르므로 컨트롤 페이지에는 결과에 담긴 것(제목, 심각도, 상태)만 보이고 "무엇을 점검하나"는 없습니다.
팩은 프로파일과 예외처럼 호스트의 선택입니다.

## 팩을 읽는 방법

팩은 쓸 권한이 있는 누구나 바꿀 수 있는 디렉터리에서 읽으므로 조심스럽게 읽습니다. 벗어날 수 없는 루트를 통해(심볼릭
링크를 따라가지 않음), 모든 디렉터리와 파일이 root 또는 본인 소유이고 그룹·기타 사용자가 쓸 수 없어야 하며(`chmod -R
go-w`), `pack.yaml`, `rules/<영역>/<이름>.yaml`, `profiles/<id>.yaml` 외의 파일은 건너뛰지 않고 오류입니다. 전체 4 MiB,
파일당 256 KiB, 점검 300개, 프로파일 50개, 디렉터리당 항목 200개까지입니다. 파일은 한 번만 열고, 해시하는 것이 곧
파싱하는 것입니다. 다른 사용자 소유 파일에 `sudo hostlint scan --pack ./pack`을 쓰거나, 다른 사용자의 CI 작업 공간 위에서
root 컨테이너로 실행하거나, Kubernetes ConfigMap(링크 모음)을 쓰면 이 때문에 거부됩니다. 팩을 본인 소유의 위치로 복사하세요.

## 형식은 아직 고정되지 않았습니다

v1.0 전에는 점검의 형식과 점검이 읽는 사실이 마이너 릴리스에서 바뀔 수 있고, 팩을 고쳐야 하면 릴리스 노트가 알려
줍니다. `requires_hostlint`는 너무 오래된 hostlint에서 팩이 실행되지 않게 합니다.
